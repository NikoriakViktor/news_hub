# Практика { #labs }

Лаби — великі самостійні завдання на коді кроків. Кожна починається з копії папки `steps/NN_*` і закінчується тестами
приймання, які мають пройти. Малі вправи («Зміни приклад», «Спробуй самостійно», «Знайди помилку») — у контрольній
точці кожного кроку; лаби їх не повторюють.

## Як влаштована лаба { #structure }

| Розділ | Що там |
|---|---|
| **Мета** | задача → зміна → результат → правило |
| **Звідки починаємо** | команда копіювання кроку і скільки тестів має пройти до змін |
| **Вимоги** | що саме зробити |
| **Критерії приймання** | повний код тестів, куди їх покласти, справжній вивід до змін (червоний) і після (зелений) |
| **Підказки** | згорнуті блоки — відкривай, коли застряг |
| **Підхід до розв'язку** | згорнутий еталонний підхід; твій розв'язок не мусить з ним збігатися |
| **Що перевірити самому** | питання й експерименти, щоб пояснити, **чому** розв'язок працює |

## Як працювати { #workflow }

```bash
cp -r steps/NN_<topic> lab_NN            # копія кроку — крок у steps/ лишається еталоном
cd lab_NN
pip install -r requirements.txt          # кроки 10–12: requirements-dev.txt
pytest -q                                # зелено — ще до змін
# поклади тести приймання зі сторінки лаби в tests/ → pytest -q → червоно
# пиши код, поки не стане зелено; mypy --strict news_hub — теж
git diff --no-index --stat ../steps/NN_<topic> .    # що ти змінив
```

Правила:

- **Тести приймання не змінюють.** Червоний тест лагодять кодом. Якщо лаба вимагає змінити наявний тест, сторінка
  каже це прямо й пояснює чому.
- **Старі тести кроку теж мають пройти** — зламаний старий тест означає регресію.
- Тести працюють без мережі: SQLite у пам'яті, fakeredis, `FakeLLM`, двійник Telegram. PostgreSQL, Redis і Docker
  потрібні лише там, де сторінка про це каже.

Як лаби перевіряє й оцінює викладач — [Викладачу](../TEACHING_GUIDE.md#grading-labs).
