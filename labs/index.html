    Практика¶

    Лаби — великі самостійні завдання на коді кроків. Кожна починається з копії папки steps/NN_* і закінчується тестами приймання, які мають пройти. Малі вправи («Зміни приклад», «Спробуй самостійно», «Знайди помилку») — у контрольній точці кожного кроку; лаби їх не повторюють.

    Огляд¶

    Упорядковано за кроком-основою: лабу можна робити одразу після цього кроку.

    Лаба Крок-основа Що тренує Складність Час
    2. Keyset-пагінація 3 курсор замість OFFSET, метод репозиторію, порядок маршрутів, тести, що ходять по сторінках ★★☆ 2–3 год
    3. Кеш та інвалідація 4 кеш пошуку, нормалізація ключа, інвалідація лише після справжньої зміни, фонова задача ★★☆ 2–3 год
    1. Atom-джерело 6 парсер XML з просторами імен, відносні URL, час з поясом, фікстура замість мережі ★★☆ 3–4 год
    4. Роль редактора 8 роль у JWT, 401 проти 403, залежність як правило доступу, тест-охоронець ★★☆ 2–3 год
    5. Команда /top 9 команда aiogram від handler до меню, чиста функція, екранування, двійник Telegram ★☆☆ 1.5–2 год
    6. Укріплений образ 10 багатоетапна збірка, права файлів, setuid, мітки OCI, --read-only, pytest -m docker ★★☆ 2–3 год
    7. Job CI: міграції 12 новий job GitHub Actions, скрипт upgrade → downgrade → upgrade → check, тест workflow ★★☆ 2 год
    8. APIRouter 12 рефакторинг без зміни поведінки, знімок OpenAPI, цикли імпортів ★★★ 3–4 год
    Фінальна: пошуковий індекс 12 EXPLAIN, trigram-індекс pg_trgm, міграція CONCURRENTLY, тест плану запиту, захист проєкту ★★★ 4–6 год

    ★☆☆ — один модуль і готовий шаблон поруч; ★★☆ — кілька модулів і рішення, яке треба ухвалити самому; ★★★ — зміна, що зачіпає весь проєкт, або результат, який доводять виміром.

    Як влаштована лаба¶

    Розділ Що там
    Мета задача → зміна → результат → правило
    Звідки починаємо команда копіювання кроку і скільки тестів має пройти до змін
    Вимоги що саме зробити
    Критерії приймання повний код тестів, куди їх покласти, справжній вивід до змін (червоний) і після (зелений)
    Підказки згорнуті блоки — відкривай, коли застряг
    Підхід до розв'язку згорнутий еталонний підхід; твій розв'язок не мусить з ним збігатися
    Що перевірити самому питання й експерименти, щоб пояснити, чому розв'язок працює

    Як працювати¶

    cp -r steps/NN_<topic> lab_NN            # копія кроку — крок у steps/ лишається еталоном
cd lab_NN
pip install -r requirements.txt          # кроки 10–12: requirements-dev.txt
pytest -q                                # зелено — ще до змін
# поклади тести приймання зі сторінки лаби в tests/ → pytest -q → червоно
# пиши код, поки не стане зелено; mypy --strict news_hub — теж
git diff --no-index --stat ../steps/NN_<topic> .    # що ти змінив

    Правила:

    • Тести приймання не змінюють. Червоний тест лагодять кодом. Якщо лаба вимагає змінити наявний тест, сторінка каже це прямо й пояснює чому.
    • Старі тести кроку теж мають пройти — зламаний старий тест означає регресію.
    • Тести працюють без мережі: SQLite у пам'яті, fakeredis, FakeLLM, двійник Telegram. PostgreSQL, Redis і Docker потрібні лише там, де сторінка про це каже.

    Як лаби перевіряє й оцінює викладач — Викладачу.
