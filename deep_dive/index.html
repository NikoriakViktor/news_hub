    News Hub Deep Dive¶

    Фінальна версія застосунку — steps/12_ci_cd. Як ми до неї дійшли — Zero to Hero, кроки 0–12. Теорія — частини I–X книги.

    Навіщо цей розділ¶

    Кроки книги показують застосунок зміна за зміною: що додали, чому, що зламалось би без цього. Після дванадцятого кроку в голові лишається історія, а не карта: де живе rate limit, хто відкриває сесію бази для фонової задачі, куди дописати нове джерело новин, щоб не забути тест.

    Deep Dive — та сама фінальна версія, але розібрана як ціле:

    Zero to Hero Deep Dive
    «що змінилось у кроці N» «як воно влаштоване зараз»
    порядок — за часом появи порядок — від процесів до рядка коду
    один модуль за раз усі модулі разом: хто кого викликає
    git diff між кроками файл:рядок у фінальному коді

    Для кого: ти пройшов кроки й хочеш побачити систему цілком — або прийшов одразу до готового застосунку і хочеш його розширити. Теорію тут не повторюємо: посилаємось на кроки й частини книги.

    Сторінки розділу¶

    Сторінка На яке питання відповідає
    Архітектура які процеси працюють, які шари в коді, хто кого імпортує (граф, отриманий з коду), карта модулів — за що відповідає кожен файл і з якого він кроку, які змінні середовища що вмикають
    Життєвий цикл запиту що відбувається з одним запитом від nginx до відповіді: middleware, rate limit, Depends, сесія, кеш, SQL, коди помилок — з журналом справжнього запуску
    Модель даних і Redis таблиці й стовпці, міграції 0001–0004, індекси, SQLite проти PostgreSQL, усі ключі Redis з TTL
    Каталог патернів Repository, Unit of Work, DI, Strategy, Adapter, Decorator, Circuit breaker, Cache-aside, Fail-fast… — де кожен у коді (файл:рядок), навіщо і з якого кроку
    Карта тестів які тести є, що в них справжнє, а що підмінене, що ловить кожен файл, який модуль якими тестами покритий, CI — які jobs що запускають
    Як розширювати нове джерело новин, ендпоінт, команда бота, міграція, змінна середовища — які файли й тести зачепити

    Порядок читання — згори донизу: кожна сторінка спирається на попередню. Якщо прийшов з конкретною задачею («додати ендпоінт»), іди одразу на Як розширювати: звідти посилання ведуть назад на потрібні місця.

    Запустити фінальну версію локально¶

    Без Docker, PostgreSQL, Redis і ключа LLM:

    cd steps/12_ci_cd
pip install -r requirements-dev.txt
python -m news_hub.security                # пароль → рядки ADMIN_PASSWORD_HASH='…' і JWT_SECRET='…'
export ADMIN_PASSWORD_HASH='$2b$12$…' JWT_SECRET='…'
export REDIS_URL=fakeredis:// LLM_PROVIDER=fake
alembic upgrade head                       # файл news_hub.db, міграції 0001 → 0004
uvicorn news_hub.api:app                   # http://127.0.0.1:8000/docs

    /docs локально є, бо DOCS_ENABLED за замовчуванням true; у Compose — false, і /docs, /redoc, /openapi.json відповідають 404 (перевірено запуском з DOCS_ENABLED=false: docs 404, openapi 404) (Архітектура → конфігурація).

    Журнали на сторінках цього розділу зняті саме так: SQLite-файл, LLM_PROVIDER=fake, але Redis — справжній (redis:7-alpine у контейнері), щоб показати ключі й TTL через redis-cli. З fakeredis:// застосунок відповідає так само, лише ключі живуть у пам'яті процесу.

    Без ADMIN_PASSWORD_HASH і JWT_SECRET застосунок теж стартує, але все, що пише, відповідає 503:

    05:18:08 INFO news_hub: 7eee880c GET /health/ready → 200 8.9 ms
05:18:08 INFO news_hub: e09c0d91 POST /api/scrape → 503 1.5 ms

    {"detail":"адмін-доступ не налаштовано: задай JWT_SECRET і ADMIN_PASSWORD_HASH"}

    Чому так, а не падіння при старті, — Архітектура → конфігурація. Уся система в Compose — крок 11, той самий шлях у CI — крок 12.
