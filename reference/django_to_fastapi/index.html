    Від Django до FastAPI¶

    Таблиця відповідностей для тих, хто знає Django і DRF. Праворуч — як це зроблено в News Hub (steps/12_ci_cd). Той самий API нотаток на обох фреймворках і розбір відмінностей — FastAPI і Django REST Framework; теми Django — у Django-книзі.

    Головна різниця: Django дає готові частини (ORM, адмінку, вхід, налаштування), FastAPI — лише HTTP-шар, перевірку даних і впровадження залежностей. Решту обираєш сам: у News Hub це SQLAlchemy 2 + Alembic, PyJWT + bcrypt, Redis, pytest.

    django-admin startproject, startapp пакет Python: news_hub/api.py (застосунок), db.py, tables.py, repository.py, … структура кроку 3
    manage.py runserver uvicorn news_hub.api:app --reload Команди
    WSGI (wsgi.py), Gunicorn ASGI, uvicorn Архітектура
    INSTALLED_APPS імпорти й app.include_router(...) Шпаргалка FastAPI
    AppConfig.ready(), сигнал старту lifespan lifespan
    manage.py <команда> модуль з if __name__ == "__main__": python -m news_hub.security, python -m news_hub.bot Команди
    manage.py shell python, потім from news_hub... import ... —

    Django-книга: структура проєкту, management-команди.

    Адреси й обробники¶

    Django / DRF FastAPI Докладно

    include("app.urls") з префіксом APIRouter(prefix="/api/news") + app.include_router(router) Шпаргалка FastAPI
    function view / APIView функція-ендпоінт (def або async def) Що таке FastAPI
    ViewSet + DefaultRouter окрема функція на кожен метод і шлях FastAPI і DRF
    @action(detail=True) ще один маршрут: POST /api/news/{news_id}/analyze —
    request.GET["q"], request.query_params параметр функції q: str = Query(...) Параметри
    request.data модель Pydantic у сигнатурі: body: NewsCreate Маршрути
    get_object_or_404(News, pk=pk) залежність get_news_or_404 → RowDep news_hub/api.py
    Response(data, status=201) return obj + status_code=201 у декораторі Відповіді
    raise NotFound(...) / Http404 raise HTTPException(404, detail=...) Коди News Hub
    APPEND_SLASH маршрут без / у кінці; /api/news/ → 307 Шпаргалка FastAPI

    Вхід і права¶

    Django / DRF FastAPI / News Hub Докладно
    django.contrib.auth, User немає; один адмін з ADMIN_USERNAME і bcrypt-хешем ADMIN_PASSWORD_HASH Адмін і JWT
    сесія в cookie, login() POST /api/admin/token → JWT, далі Authorization: Bearer … Адмін і JWT
    request.user значення залежності: require_admin повертає sub з токена Залежності
    permission_classes = [IsAuthenticated] dependencies=[AdminDep] на ендпоінті news_hub/security.py
    @login_required, IsAdminUser та сама залежність: 401 без токена, 403 без ролі admin Коди News Hub
    make_password, PASSWORD_HASHERS bcrypt напряму (hash_password, authenticate) news_hub/security.py
    CSRF-захист для Bearer-токена не потрібен; для cookie — SameSite і CSRF-токен CORS
    django-cors-headers CORSMiddleware CORS
    DRF throttling rate_limit middleware на Redis: 429 + Retry-After Rate limit

    Що обрати¶

    Схема вибору й приклад — FastAPI і DRF: як обрати. Коротко: сайт, адмінка й користувачі над однією базою — Django + DRF; окремий API-сервіс з великою кількістю мережевого I/O (як News Hub: сайти, LLM, Telegram) — FastAPI.
